기준: Raspberry Pi OS 64비트 (Desktop), 라즈베리 파이 5, 코드 = `tram_system` (2026-11-04 판)

## 1. 한눈에

| 파이에 넣을 것 | 크기 | 어떻게 |
| --- | --- | --- |
| `tram_pi.zip` (코드 + 파이용 YOLO 모델) | 약 11 MB | USB 메모리 |

## 3. 전달 방법: USB 메모리 추천

**처음엔 USB 메모리가 가장 쉽고 빠릅니다.**

- 인터넷 로그인 필요 없음. 파이 Desktop에 꽂으면 바로 파일 창이 뜨고 `/media/<사용자이름>/<USB이름>/` 에 보입니다.
- 1 GB짜리 원본 영상도 몇십 초면 복사됩니다. 클라우드는 노트북에서 올리고 파이 브라우저로 다시 받아야 해서 두 배로 오래 걸리고, 네이버 MYBOX는 파이 브라우저에서 로그인(2단계 인증 등)이 번거롭습니다.
- USB 형식: FAT32는 4 GB 넘는 파일을 못 담습니다(원본 영상 1.09 GB는 괜찮음). exFAT·NTFS도 파이 OS에서 읽힙니다.
- 빼기 전에 파이 파일 창에서 **꺼내기(⏏)** 를 누르세요(안 누르면 파일이 덜 써질 수 있음).

클라우드(MYBOX 등)는 **백업·팀원 공유용**으로 쓰면 좋습니다.
나중에 코드를 자주 고치게 되면 USB 대신 같은 와이파이(노트북 모바일 핫스팟)에서 `scp`나 VS Code의 Remote-SSH로 노트북에서 바로 보내는 게 편합니다 (7장).

## 4. 파이 설치 (터미널에서 한 줄씩)

파이 화면 왼쪽 위 터미널 아이콘(검은 창)을 엽니다. USB에 `tram_pi.zip`을 넣어 꽂았다고 가정합니다.

```bash
# 1) zip을 홈 폴더로 복사하고 풀기  ->  ~/tram_pi 폴더가 생김
cp /media/$USER/*/tram_pi.zip ~/
cd ~ && unzip -o tram_pi.zip

# 2) OS 쪽 부품 (카메라 picamera2, OpenCV, 부저·LED gpiozero)  -- 5~10분
sudo apt update && sudo apt full-upgrade -y
sudo apt install -y python3-picamera2 python3-opencv python3-gpiozero python3-venv

# 3) 가상환경. 반드시 --system-site-packages (그래야 apt로 깐 picamera2·gpiozero가 보임)
cd ~/tram_pi
python3 -m venv --system-site-packages .venv
source .venv/bin/activate          # 줄 앞에 (.venv) 가 보이면 성공

# 4) 파이썬 부품 (pyzmq, ultralytics, ncnn)  -- torch가 커서 10~20분
pip install -r requirements_pi.txt

# 5) 확인
python tools/selftest.py                          # 약 1분. 마지막 줄 '합격'이면 설치 끝
python tools/check_env.py --ncnn yolo11n_ncnn_model   # YOLO 1장에 몇 ms인지 나옴
```

- 터미널을 새로 열 때마다 `cd ~/tram_pi && source .venv/bin/activate` 를 먼저 합니다.
- `picamera2`를 부를 때 `numpy.dtype size changed` 오류가 나면: `pip install "numpy<2"` 후 다시.
- 파이 5는 YOLO를 돌리면 뜨거워집니다. **액티브 쿨러를 꼭 달고**, 온도는 `vcgencmd measure_temp` 로 봅니다 (80 ℃ 넘으면 느려짐).

## 5. 블랙박스 영상을 파이에서 돌려 보기

### 어떤 프로그램으로?
- 블랙박스 영상(실제 선로)은 **`pc_main.py`** 로 돌립니다. 실제 레일 찾기·거리 연장·위험 장면 저장이 들어 있는 쪽입니다.
- `pi_main.py --source 영상.mp4` 도 영상 파일을 받긴 하지만, 선로 찾기가 **노란 테이프(1:10 모형)용**이라 실제 영상에선 `NO VIEW`(감시 불가)만 나옵니다. 합성 영상·모형 영상용입니다.

### ① 노트북에서 영상 줄이기 (권장)
파이 5에는 H.264 영상 하드웨어 디코더가 없어서, 1920x1080 원본을 그대로 넣으면 영상 푸는 데만 CPU를 많이 씁니다.
그래서 노트북에서 폭 960(또는 640)으로 줄이고 보고 싶은 구간만 자릅니다.
zip 안의 `tools/make_pi_clip.py` 를 노트북 `G:\tram_\tools\` 에 복사한 뒤 (VS Code 터미널, 가상환경 켠 상태):

```bat
cd /d G:\tram_
.venv\Scripts\activate.bat
python tools\make_pi_clip.py                                  :: 9분 40초부터 60초, 폭 960
python tools\make_pi_clip.py --start 3:30 --duration 120 --width 640
```
결과 `G:\tram_\pi_clips\tram_09m40s_60s_960.mp4` 를 USB에 넣습니다. (예전에 `video_probe.py`로 만든 `logs\probe\clips\` 의 20초짜리 960x540 영상들도 그대로 써도 됩니다.)

### ② 파이에서 실행
```bash
mkdir -p ~/videos && cp /media/$USER/*/tram_*.mp4 ~/videos/
cd ~/tram_pi && source .venv/bin/activate

python pc_main.py --video ~/videos/tram_09m40s_60s_960.mp4 --model yolo11n_ncnn_model --imgsz 320 --width 640
```
- `--model yolo11n_ncnn_model --imgsz 320` 은 꼭 붙이세요 (빼면 노트북용 모델을 찾다가 yolo11n.pt를 새로 받음).
- 키는 노트북과 같습니다: 스페이스 멈춤, d/a 10초 앞뒤, s 캡처, q 끝. 결과는 `~/tram_pi/logs/pc/<날짜>/`.
- 원본 1080p를 그냥 넣어도 돌아는 갑니다: `--video ~/videos/tram_blackbox.mp4 --start 9:40` (대신 더 느림).
- 모든 프레임을 빠짐없이 처리하려면 `--no-realtime` (영상이 느리게 재생됨).

### 성능 기대치 (추정, 파이에서 실측 필요)
| 상황 | 예상 |
| --- | --- |
| 클라우드 PC 4코어에서 이 zip 그대로 (960 영상, 폭 960, NCNN 320) | 실측 약 28장/초 |
| 파이 5 + 줄인 영상(960) + `--width 640` + NCNN 320 | 약 6~12장/초 (추정) |
| 파이 5 + 1080p 원본 그대로 | 약 3~6장/초 (추정) |

- 실시간 모드(기본)는 처리가 늦으면 프레임을 건너뛰어서, 영상은 정상 속도로 흘러가고 박스가 띄엄띄엄 갱신됩니다. 목표(10장/초)에 못 미치면 `--width 640` 영상으로 줄이거나 노트북 분담(원래 구조)이 필요하다는 근거가 됩니다.
- 화면 아래 요약의 '평균 FPS'를 발표 자료의 "파이 단독 성능" 숫자로 쓸 수 있습니다.

## 6. 카메라 모듈 3·부저·LED를 붙인 뒤

```bash
python tools/check_env.py --picam --gpio          # 사진 1장 찍기, LED·부저 차례로 켜기
python pi_main.py --source picam --server none --local yolo --local-imgsz 320          # 파이 단독
python pi_main.py --source picam --server tcp://192.168.137.1:5555 --local yolo --local-imgsz 320   # 노트북과 나눠서
```
노트북 쪽 실행·왕복 시간 측정(`tools/latency_test.py`)은 `tram_system/README.md` 4장 그대로입니다.

## 7. 나중에 코드를 고쳐서 다시 보낼 때 (USB 없이)

파이 설정(Raspberry Pi 설정 → 인터페이스)에서 **SSH 켜기**, 파이와 노트북을 같은 와이파이(노트북 모바일 핫스팟)에 연결 후 파이 주소 확인(`hostname -I`). 노트북 PowerShell에서:
```powershell
scp -r G:\tram_\tram  <사용자이름>@<파이주소>:~/tram_pi/       # 바뀐 폴더만 덮어쓰기
```
VS Code의 'Remote - SSH' 확장을 쓰면 파이의 파일을 노트북에서 바로 열어 고칠 수도 있습니다.

## 8. 자주 나는 문제

| 증상 | 해결 |
| --- | --- |
| `No module named picamera2` | 가상환경을 `--system-site-packages` 없이 만든 것. `.venv` 지우고 4장 3)부터 다시 |
| `externally-managed-environment` | 가상환경을 안 켠 상태. `source .venv/bin/activate` 후 pip |
| pip 설치가 중간에 멈춤·느림 | 와이파이 확인 후 같은 명령 다시 (받은 건 이어서 씀) |
| 영상 창이 안 뜸 | SSH로 접속한 상태면 `--no-show`. 모니터 연결된 Desktop 터미널에서 실행 |
| 화면이 '감시 불가' | `pi_main`에 실제 영상을 넣은 경우 → `pc_main` 사용 (5장) |
| 갑자기 느려짐 | 과열. 쿨러 확인, `vcgencmd measure_temp` |
