# 포트폴리오·자기소개서 활용 가이드

이 저장소를 팀원 각자가 포트폴리오, 이력서, 자기소개서, 면접에서 쓰기 위한 안내입니다.
**원칙은 하나입니다. 실제로 한 일과 실제로 나온 숫자만, 근거를 붙여서 쓰기.**

---

## 1. 이력란 한 줄 (복사해서 쓰기)

- 짧게: **카메라 기반 트램 전방 충돌 위험 알림 시스템 개발 (2026.09~11)**
- 조금 길게: **YOLO 물체 인식 + 선로 기하 기반 거리·충돌 예상 시간(TTC) 계산으로 4단계 위험 알림을 하는 트램 전방 감시 시스템 개발 (Python, OpenCV, 칼만 필터, 라즈베리파이 5)**
- 링크: 이력서·포트폴리오에 이 저장소 주소를 함께 적고, 본인 역할을 한 줄 덧붙이기 (예: "선로 검출 담당", "하드웨어·모형 담당", "발표·문서 담당")

프로젝트는 1단계 구현 후 마무리되었습니다. 자소서에 쓸 때는 "1단계(전방 위험 판정)까지 구현하고, 다음 단계(원거리 열차 접근 알림)는 설계만 했다"처럼 사실대로 쓰면 됩니다. 중단 자체는 감점 요인이 아니고, 어디까지 했고 무엇을 배웠는지가 중요합니다.

## 2. 쓸 수 있는 경험 (상황 → 문제 → 행동 → 결과)

각 사례에서 **본인이 실제로 맡은 부분만** 골라 쓰세요.

| 사례 | 내용 | 어울리는 문항 |
| --- | --- | --- |
| A. 아이디어를 숫자로 검증 | "통신이 끊기면 칼만 필터로 예측하자"는 아이디어를 3,000회 시뮬레이션으로 검증. 마지막 값 유지는 0.3초에 위험 구역 안 사람 19% 놓침, 칼만 예측은 약 0%였지만 1초 넘으면 헛경보 58%로 급증 → 계획을 "바로 예측, 1초부터 자체 검출"로 수정 | 문제 해결, 분석력 |
| B. 직접 발견한 문제의 원인 측정 | 실제 주행 영상에서 "위험 구역 모양이 흔들린다", "거리 눈금이 부정확하다"를 발견 → 기록을 재 보니 카메라 높이를 매 프레임 새로 계산해 1.1~7.4 m까지 오감 → "변하지 않는 값은 고정" 원칙으로 50 m 눈금 흔들림 3~26 px → 0.3~1.2 px (재계산, 코드 반영 전) | 문제 해결, 꼼꼼함 |
| C. 헛경보 줄이기 | 실제 영상에서 '위험'이 프레임의 32~40% → 원인 3가지(지나간 물체의 유령 예측, 화면 끝에 잘린 박스, 처음 몇 프레임의 속도 출렁임)를 찾아 걸러 '위험' 0%, '경고' 0~5% (20초 구간 4개 실측) | 문제 해결, SW 개발 |
| D. 조건이 바뀌어도 이어 가기 | 예산이 100만 → 60만 → 보드 제외 20~30만 원으로 줄자 깊이 카메라 대신 "선로 폭(1.435 m)을 자로 쓰는" 거리 계산으로 바꾸고, 노트북·파이 연산 분담으로 설계 변경 | 가치관·태도, 적응력 |
| E. 막힌 경험을 팀 가이드로 | 개발 환경 설치에서 막힌 문제(Python 버전, cmd/PowerShell 차이, 실행 위치)를 해결하고 팀원용 설치 안내서로 정리 | 협업 |
| F. 처음 듣는 사람에게 설명 | 산학 컨설팅에서 기업 실무자에게 필요성 중심으로 발표, 주간 진행 발표·지도 교수 진도 보고 | 의사소통, 협업 |
| G. 방향 재정의 | 1단계 후 "가까운 물체 판정보다 멀리 있는 사람을 미리 찾아 피하게 하는 것이 현장에 더 필요하다"는 결론 → 소실점 주변 집중 관찰, 속도 추정+IMU, 야간 카메라로 2단계 설계 | 문제 정의, 기획력 |

## 3. 숫자 쓸 때 꼭 붙일 꼬리표

| 숫자 | 정확한 표현 |
| --- | --- |
| 거리 오차 1.1~1.3 %, 놓침 0건 | **합성 영상** 자체 시험 결과. "실제 상황에서 놓침 0건"이라고 쓰면 안 됨 |
| 헛경보 32~40 % → 0 % | 실제 트램 영상 **20초 구간 4개** 실측. 진짜 위험 장면을 놓치지 않는지는 미검증 |
| 놓침 19 % vs 약 0 % | **시뮬레이션** 3,000회 |
| 선로 인식 0 → 55 → 75 % | 공개 선로 사진 **60장** 실측 |
| YOLO 초당 70장 | 노트북 GPU(OpenVINO) 실측, 전체 시스템 속도 아님 |
| 라즈베리파이 속도, 통신 지연 | **못 잼.** 쓰지 않기 |

## 4. AI 활용은 숨기지 말고 강점으로

이 프로젝트의 코드 초안, 시뮬레이션, 분석, 문서 초안은 생성형 AI(Claude)를 활용해 만들었습니다. 팀은 방향과 요구사항을 정하고, 직접 실행해 문제를 찾고, 결과를 검증해 다음 결정을 내렸습니다.

- 좋은 표현: "AI를 활용해 구현했고, 저는 요구사항과 구조를 정하고 결과를 직접 실행·검증해 문제를 찾아 개선 방향을 정했습니다."
- 피할 표현: 직접 짜지 않은 코드를 "직접 코딩했다"고 쓰기. 면접에서 코드 한 줄을 물으면 바로 드러납니다.
- 대신 면접 전에 아래 5가지는 **자기 말로** 설명할 수 있게 준비하세요. 이게 되면 "AI가 다 한 것 아니냐"는 질문에도 자신 있게 답할 수 있습니다.

## 5. 면접 예상 질문과 짧은 답

- **카메라 하나로 거리를 어떻게 재나요?** 선로 폭(궤간)이 1.435 m로 정해져 있어서, 물체 발밑에서 두 레일 사이가 몇 픽셀인지 보면 1 px이 몇 m인지 압니다. 옆 거리와 위험 구역 판정은 비율이라 카메라 초점거리 없이도 맞고, 앞 거리만 카메라 보정이 필요합니다.
- **왜 선형 칼만 필터인가요?** 픽셀을 먼저 미터로 바꿔 넣으니 측정이 선형이라 EKF·UKF가 필요 없습니다. 0.1초 간격에서는 속도가 거의 안 바뀌어 등속 모델로 충분하고, 멀수록 측정을 덜 믿도록 잡음을 거리 제곱에 비례하게 잡았습니다.
- **TTC 3초·5초의 근거는요?** 자동차 충돌 경고에서 쓰는 TTC 개념을 빌린 출발값입니다. 시속 50 km에서 반응 1초 + 일반 제동이면 약 94 m가 필요해 3초 안쪽은 멈추기 어렵다는 계산이고, 실제 운행 기준은 아니라 시험하며 조정할 값입니다.
- **왜 인식과 판단을 다른 보드로 나눴나요?** 무거운 인식만 밖으로 넘기고 판단·경보는 트램 위 장치에 남겨, 통신이 끊겨도 경보가 사라지지 않게 하려고요. 끊기면 칼만 예측 → 1초 뒤 자체 검출로 넘어갑니다.
- **한계는 뭔가요?** 실제 위험 장면에서의 놓침 검증, 라즈베리파이 실측 속도, 야간·비·안개, 50 m 넘는 작은 사람, 그늘 속 레일과 분기기. 그래서 2단계로 소실점 주변 집중 관찰과 야간 카메라를 구상했습니다.
